1. Cel projektu

Produkt ma być narzędziem treningowym — nie zwykłą listą notatek. Priorytetem jest szybkość obsługi na telefonie, czytelność podczas wysiłku oraz wiarygodna historia wykonania.

Faza 1

Planowanie — dyscyplina, cel, bloki, ćwiczenia, rundy i przerwy.

Faza 2

Wykonanie — guided player z okrągłym timerem i kontrolą przebiegu.

Faza 3

Ewidencja — zapis sesji w Historii, notatki, zarządzanie wpisami.

Dyscypliny MVP: Boks, Kickboxing, Muay Thai, K-1, MMA stójka.

3. Uruchomienie dema

cd combat-training-app
npm install
npm run dev

Adres lokalny zwykle: http://localhost:5173

4. Scenariusz prezentacji (3–5 min)

  1. Home — przełącz motyw ciemny / jasny.
  2. Treningi → Plany — pokaż listę i filtry.
  3. Utwórz plan w kreatorze (dyscyplina, bloki, ćwiczenia).
  4. Zapisz → otwórz szczegóły → uruchom trening.
  5. Player: PRACA / ODPOCZYNEK / pauza / ukończenie.
  6. Historia: zapisana sesja, notatka, usuwanie.

6. Architektura (skrót)

src/ ├── app/ router, providery ├── components/ layout, UI, ikony ├── domain/ typy i reguły domenowe ├── features/ home, workouts, builder, player, theme ├── infrastructure/ localStorage (plany i sesje) └── pages/ strony tras
  • UI nie zawiera logiki czasu ani reguł domenowych w JSX „na sztywno”.
  • Storage implementuje interfejsy repozytoriów.
  • Player ma osobny moduł stanu (nie globalny store).
  • Motywy: tokeny semantyczne CSS + data-theme.

7. Design

  • domyślny motyw: ciemny; pełny light mode z persystencją wyboru,
  • akcent marki: crimson,
  • typografia: Inter + Archivo,
  • układ zoptymalizowany pod smartfon, z wersją desktopową.

8. Kolejne etapy

  • pełne podsumowanie / feedback po treningu,
  • raport historii,
  • edycja zapisanego planu,
  • Supabase + anonimowa sesja,
  • PWA, gong, Wake Lock (zgodnie ze specyfikacją produktu).

9. Podsumowanie

Demo pokazuje działający rdzeń produktu: utwórz plan → poprowadź trening timerem → zapisz i przeglądaj historię, z motywami dark/light oraz interfejsem przygotowanym pod użycie mobilne.
